# Coinbase Exchange contract

The target is Coinbase Exchange spot REST and WebSocket JSON as documented and observed on 2026-11-24. Coinbase publishes these endpoints without an explicit version in the path. The release pins the field names, signing rules and semantics below. The initial product universe is `BTC-USD` and `BCH-USD`. Both products appeared online in the public Exchange sandbox capture. The sandbox metadata recorded price increments of `0.01` USD, size increments of `0.00000001` BTC or BCH, and `min_market_funds` of `1` USD. A deployed session must read current product metadata before admitting orders. The local risk ceiling can exceed the venue's minimum and is checked separately from increments. [Sandbox](https://docs.cdp.coinbase.com/exchange/introduction/sandbox) · [Product endpoint](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-single-product)

| Capability | Contract |
|---|---|
| Environments | Production REST is `https://api.exchange.coinbase.com` and its public feed is `wss://ws-feed.exchange.coinbase.com`. Sandbox equivalents are `https://api-public.sandbox.exchange.coinbase.com` and `wss://ws-feed-public.sandbox.exchange.coinbase.com`. Credentials and balances are separate. Production trades require operator authorization. |
| Authentication | Profile-bound key with trade and any needed view permission. Exchange REST signs the timestamp, method, path and exact body bytes using HMAC-SHA256 with a base64-decoded secret, then base64-encodes the digest. Timestamp skew tolerance is 30 seconds. The signature, key, passphrase and timestamp travel as `CB-ACCESS-*` headers. Authenticated WebSocket subscriptions sign `GET /users/self/verify` and pass auth fields in the subscription. |
| Order book | Subscribe to `full`, queue frames while fetching `GET /products/{product_id}/book?level=3`, and apply frames beyond the REST snapshot sequence in per-product order. `received` consumes sequence but adds no resting order. `open` adds a level-3 resting order, `match` reduces its maker, and `done` or `change` touches a resting order only when present. Gap or transport loss invalidates the book. The public sandbox returned an authentication-required error for a `full` subscription on 2026-11-24. |
| Order identity | A submit uses `POST /orders`, type `limit`, a lowercase variant-compatible version-4 `client_oid`, `product_id`, `side`, `price` and `size`. The response's `id` is the venue identity. Lookup is `GET /orders/client:{client_oid}`. A `404` can also mean a previously cancelled, unfilled order was purged. No retry guarantee for a timed-out create is assumed. |
| Cancel | Use `DELETE /orders/client:{client_oid}?product_id={product_id}` or the exchange ID on the same endpoint. Cancel response acknowledges the request outcome. A reconciled terminal order and complete fills are required before releasing a residual reservation. |
| Fills | `GET /fills` by `order_id` or `product_id` supplies trade ID, order ID, product, price, size, side, fee and settlement state. Accrue cash and inventory from settled fills. Use `(product_id, order_id, trade_id)` as the account-side identity and compare duplicate payloads. Cursor pages are descending by `trade_id`. Account history/recovery must overlap pages across runs and compare account balances and open orders. |
| Amendments | This release uses Exchange REST limit submit and cancel. Exchange documents amendments through FIX order entry. An amendment on the REST release requires confirmed cancel followed by a fresh order identity and admission. |
| Retention | Published order lookup can lose cancelled zero-fill orders. The consulted REST fills documentation specifies pagination and date filters, with no guaranteed minimum retention period. Record needed pages independently and restrict exposure on missing or contradictory evidence. |
| Rate limits | Default REST limits per second are public 10 (burst 15), private 15 (burst 30), and private `/fills` 10 (burst 20). WebSocket docs list 8 requests per second per IP (burst 20), 100 inbound messages per second per IP, and limits on subscriptions per product and channel. Book and private requests need separate bounded queues. |

The fixture directory contains public REST response bodies for the two product definitions and real level-3 snapshots. BTC-USD was captured at `2026-11-24T22:01:43.358743908Z`, sequence `2465339208`, with 51 bids and 46 asks. BCH-USD was captured at `2026-11-24T22:01:42.818491052Z`, sequence `962169497`, with 20 bids and 25 asks. The test's subsequent events and private account statements are synthetic. Authenticated feed, production order entry, retention bounds and reconciliation against a real private account remain qualification gates.
