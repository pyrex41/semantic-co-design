# Recovery policy construction trial v1

This bounded pilot measures construction of a recovery controller. Each candidate submits a JSON policy keyed by task/tick/signal with values retry, settle or hold. The first attempt lost its response. The environment has stopped failing and there is one decision left. Settle acknowledges completion without issuing another attempt. Hold preserves the pending obligation for later reconciliation. A retry receives its response. The controller must avoid duplicate effects and false completion, and reach completion whenever the observations and provider contract make that safe.

The voucher provider atomically deduplicates repeated attempts with the same identity before tick 3. At tick 3 the receipt expires. The dispatch provider has no deduplication. Each task exposes ticks 2, 3 and 4. An authoritative reconciliation can report applied or absent. An unavailable reconciliation leaves the first attempt's result unknown. Only the grader can inspect that result. These benchmark requirements are fixed for the pilot; acceptance of an application cancellation policy is a separate decision.

## Matched conditions

Use isolated participants of the same model/version and reasoning setting, one fresh context per arm and repetition. Each receives the identical task statement above, the same AcceptedJob and outbox training examples, and the same test/replay interface. One arm receives examples only. One also receives a hand-authored library. The third also receives an inferred library built from those examples in a separate context before exposure to the tasks. Freeze both libraries by digest before evaluation. Restrict participants to supplied materials. The protocol and grader are withheld from the library builder. A participant who has read the grader is ineligible.

Allow three submissions, 10 minutes and 8,000 output tokens per participant. Stop at the first passing submission or exhausted budget. After each failed submission expose one failing public observation, action, resulting evidence and rejection reason. Keep hidden-world inputs out of the controller. Run three repetitions per arm and retain model identity, library digest, submissions, usage, elapsed time, feedback and human decisions. Report library construction costs separately. Disqualify an arm instance that repeats the same unsafe guarantee after receiving its counterexample. An unsafe guarantee means a controller declaring completion without an effect or causing duplicate effects on an admitted history.

Score both tasks independently across every admissible hidden world. Compare tasks passed, false completions, duplicates, missed progress, repair attempts, time and human decisions. Report individual runs and identical-task paired differences. A bounded controller success supports only this pilot. A claim about general software construction requires additional tasks and independent participants.
