# Specializing the patterns in PAIP

Give a compiler a fixed behavior specification, then call the resulting `Residual.run` with new inputs. `Residual.source` contains the generated Python, which CPython compiles once when the artifact is built. Static grammar productions, operator effects, rule alternatives, lexical addresses, board geometry, and other profile choices become direct code or precomputed data. Matching, search, unification, parsing, and effects still depend on the input. Trusted callable hooks are explicit dependencies. The flat integer matcher has a separate Shen-to-C path suitable for linking into a C caller. [Shen-to-C matcher](../README.md)

From the repository root, run the behavioral gate with `nix develop --command python3 -m experiments.patterns.paip.check`. To build an artifact from a profile and call it directly:

```python
from experiments.patterns.paip.rules import compile_translator

translator = compile_translator([
    (("transfer", "?id", "to", "?id"), ("record_transfer", "?id")),
])
assert translator.run(("transfer", 42, "to", 42)) == ("record_transfer", 42)
assert translator.run(("transfer", 42, "to", 19)) is None
print(translator.source)
```

## Compilers and behavioral checks

The gate builds changed profiles and looks for corresponding changes through the same runtime interface. It includes negative controls such as a pattern that must backtrack over an earlier delimiter, simultaneously impossible constraints, and a continuation that resumes twice while sharing a mutable lexical binding. Each compiler documents its input schema and result type. Except where specified, the experiments use bounded or deliberately restricted source languages. There are no performance measurements in this catalog.

| Pattern | Compiler | Defining behavior exercised by the gate |
| --- | --- | --- |
| Recursive phrase generation | [`grammar.compile_generator`](grammar.py) | Enumerates sentences or parse trees from the same productions. Seeded generation chooses feasible alternatives. `check_generation` inspects rule order, depth, and recursion. |
| Ordered graph and heuristic search | [`search.specialize_search`](search.py) | BFS, DFS, best-first, beam, and A* preserve paths and costs under their declared frontier policies. `check_graph_search` distinguishes shortest paths, reordered ties, a lost beam branch, and an unreachable goal. |
| Means–ends and forward state-space planning | [`search.specialize_planner`](search.py) | Known preconditions, add effects, and delete effects become bit operations. `check_planning` distinguishes backward GPS from forward search when subgoals interfere. |
| Segment and predicate matching | [`rules.compile_matcher`](rules.py) | `check_segment_matcher` verifies shortest-first star/plus, optional selection, predicates, and repeated binding equality, including a successful retry after a previously plausible split. |
| Ordered rule translation | [`rules.compile_translator`](rules.py) | `check_ordered_translator` verifies first matching rule, one reflection per bound value, unmatched input, punctuation in literal values, and changed order. |
| Word equations with propagation | [`rules.compile_student`](rules.py) | `check_student` verifies recursive phrase translation and exact affine substitution. Changed templates alter the result. Coupled unknowns remain unresolved. |
| Infix operator precedence | [`symbolic.compile_infix`](symbolic.py) | `check_infix` checks grouped expressions, associativity, precedence changes, aliases, and malformed input. |
| Ordered recursive rewriting | [`symbolic.compile_rewriter`](symbolic.py) | `check_rewriting` verifies simplification of child expressions, operator functions, repeated variables, ordered rewrites, subtree memoization, and diagnosed cycles and budget exhaustion. |
| Antiderivative table and factor substitution | [`symbolic.compile_integrator`](symbolic.py) | `check_integration` verifies powers, rules for unary functions, removal of constant factors, a matching derivative, and residual integrals where substitution fails. |
| Horn clause compilation | [`logic.compile_horn`](logic.py) | `check_horn` verifies fresh variables, structure, repeated bindings, answer order, and backtracking. `check_cut` verifies commitment within a predicate. Fixed predicates call one another directly. |
| Indexed reasoning in worlds | [`logic.compile_worlds`](logic.py) | `check_indexed_worlds` verifies inherited facts, explicit negatives, conjunction, typed and custom procedural attachments, and structural retrieval. |
| Canonical symbolic algebra | [`symbolic.compile_canonical`](symbolic.py) | `check_canonical_algebra` verifies multivariate polynomial equality, differentiation and univariate rational cancellation with exact coefficients and a monic denominator. |
| Uncertain backward chaining | [`expert.compile_expert`](expert.py) | `check_expert_system` checks certainty combination, cutoff, early rejection, and shared subgoal consultation within one instance. |
| Constraint propagation and complete bounded search | [`constraints.specialize_constraints`](constraints.py) | `check_constraint_search` checks fixed compatibility masks and current observations against complete assignments. Pairwise consistency can coexist with no solution. |
| Waltz line labeling | [`constraints.specialize_waltz`](constraints.py) | `check_waltz_labeling` checks the catalog of junction labels and their agreement on shared edges, with a contradictory observation. |
| Adversarial search | [`search.specialize_game`](search.py) | `check_adversarial_search` compares generated minimax and alpha-beta to an independent Othello model. Runtime boards, legal moves, passes, and terminal scoring drive the result. |
| Finite edge-score precomputation | [`edge.compile_edge_table`](edge.py) | `check_edge_table` counts the build-time enumeration and exercises reordered board windows. Runtime performs only base-three indexing and summation after validating the board. |
| Ambiguous parsing with preferences | [`grammar.compile_preference_parser`](grammar.py) | `check_preferences` checks distinct compositional meanings, preference ranking, recursive ambiguity, full-input acceptance, and category-specific handling of unfamiliar words. |
| Deductive grammars and English feature profiles | [`logic.compile_unification_grammar`](logic.py) | `check_deductive_grammar` and `check_english_features` verify difference lists, multiple scopes, number agreement, pronoun case, verb frames, and a wh-gap dependency. |
| Lexical compilation, tail calls, continuations | [`scheme.compile_scheme`](scheme.py) | `check_scheme_compiler` verifies effects, static branch removal, shadowing, stack-independent recursion, nonlocal escape, and multi-shot resumption. |

Core and aggregate checks live in [check.py](check.py). Grammar and logic checks live in [check_grammar_logic.py](check_grammar_logic.py). Search and constraint checks live in [check_search_constraints.py](check_search_constraints.py).

## Chapter-by-chapter inventory

The inventory uses the author's full text and accompanying Common Lisp at commit `9cea73837e439d331fe78d7b585e994c7113aac2`. A separate compiler earns a place when fixing its input removes a distinct piece of interpretation or precomputes a result that dynamic inputs reuse. Domain examples that exercise the same specialization share the compiler. [Peter Norvig's full text and source](https://github.com/norvig/paip-lisp/tree/9cea73837e439d331fe78d7b585e994c7113aac2) · [Author's Lisp source index](https://www.norvig.com/paip/README.html)
